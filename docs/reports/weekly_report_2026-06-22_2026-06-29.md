## 本周主要工作

### 1. 非转场镜头连续性实验与 Smooth 方案

本周围绕非 cut 镜头的连续性问题做了一组探索，结论是：仅靠静态参考帧或首帧约束不足以保证视频运动连续，连续镜头需要显式利用上一段视频的时序信息。

主要尝试包括：

- **Default + prompt 约束首帧**：即使在 prompt 中强调参考上一段尾帧，Seedance 仍可能在开头产生明显跳变；将本地尾帧上传改为使用 Seedance 返回的 `last_frame_url` 也没有明显改善。
- **Last frame only**：可以较好保证新视频首帧等于上一段尾帧，但无法继承上一段末尾的运动状态，镜头运动仍会出现卡顿或不连续。
- **上一段尾部 1 秒视频输入**：测试 Seedance 的 `reference_video` 输入后，发现相比单帧输入，运动连续性有一定改善，但模型并不会严格复制输入段，接缝处仍可能有跳变。
- **要求输出包含输入视频段**：实验发现 Seedance 会重新渲染输入尾段，而不是原样保留，且可能引入外观漂移，因此暂记为不优先采用。
- **拼接位置与插帧实验**：尝试过 SSIM、运动差异、综合 cost 等方式选择拼接点，但视觉差异不明显；随后比较 FFmpeg 与 RIFE 插帧，人工观感上 RIFE 更平滑，FFmpeg 接缝处有更明显重影。

最终形成的暂定方案是 **Smooth 模式**：

- 对非 cut shot，向 Seedance 输入上一段原始视频的最后 1 秒作为 `reference_video`。
- Prompt 中明确说明：当前 shot 是在延续 Video 1 的末尾动作、物体运动和镜头运动，不要回退、重复或复刻输入段。
- 生成后，最终拼接时删除上一段最后一帧和当前段第一帧，以 `A[-2]` 和 `B[1]` 为锚点，用 RIFE 插入两帧进行等长替换。
- Smooth 只解决短期运动连续性；历史参考图仍由独立的记忆检索机制负责。

目前该方案已经成为连续镜头的主要基线，同时保留 Default 和 Last frame only 作为消融。

### 2. 基于视觉元素集合的历史帧选择与 Prompt 构建

针对历史帧错误引用和 Memory Selector 改进，本周形成了新的 **Visual Element Memory** 方法框架，并完成了初步验证与文档整理。

核心思路是：不再把历史关键帧视为整体图像进行相似度检索，而是维护一个显式的视觉元素集合，并基于“当前 shot 需要什么 / 不应出现什么”来选择参考帧。

方法包括：

- **视觉元素集合构建**：通过 LLM 从剧本 prompt 中维护角色、场景、物体三类元素，例如“小王子”“狐狸”“地球的广阔金色沙漠”等。
- **元素状态管理**：对每个 shot，将已有元素标为“应参考 / 不应引入 / 可选不确定 / 新元素”。
- **VLM 闭集标注**：使用 Seed2.1 Turbo 对历史关键帧进行标注，只判断当前集合中的已知元素是否出现，并输出 bbox；场景元素统一视为整图。
- **历史帧评判**：每张历史帧根据当前 shot 的元素状态被解释为包含哪些应参考元素、哪些不应引入元素、哪些可选元素。
- **选帧算法**：设计了简洁的三项打分：

  ```text
  Score(f | covered)
    = 应参考元素奖励
    + 可选元素弱奖励
    - 应排除元素惩罚
  ```

  其中开启集合覆盖时，未覆盖的应参考元素使用高权重，已覆盖元素使用低权重；不开启时则退化为 Static Top-K baseline。

- **Prompt 组织**：形成五段式 Seedance prompt：

  ```text
  [0. 完整剧本上下文]
  [1. 当前 shot 的生成任务]
  [2. 本 shot 的视觉元素计划]
  [3. 参考图使用说明]
  [4. 总体约束]
  ```

  这样可以同时告诉 Seedance：当前镜头要生成什么、哪些历史元素应保持一致、哪些历史元素不应引入，以及每张参考图中具体应参考哪些部分。

目前已经在小王子实验中完成了元素集合维护、关键帧 VLM 标注、历史帧评判和可视化；后续也已将该机制接入 CLI 的可选实验路径，可输出选中参考帧、标注图、完整提交 prompt 和 `memory_report.md` 记录。

## 当前结论

- 连续镜头问题不能只靠单张参考帧解决，需要显式输入上一段尾部视频，并在最终拼接处进行插帧修正。
- RIFE 插值在当前样例中优于 FFmpeg，是 Smooth 模式的暂定默认后处理方案。
- 错误引用历史帧的问题更适合通过“显式视觉元素集合 + 闭集 VLM 标注 + 精确指代 prompt”来处理，而不是单纯增强自然语言 prompt。
- Memory Selector 的下一步重点应是验证 Visual Element Memory 相比普通图文检索 / Static Top-K 是否能减少错误引用并提高一致性。

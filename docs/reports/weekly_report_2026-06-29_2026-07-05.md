# 周报：2026.06.29 - 2026.07.05

## 本周主线

本周的研究重点从“验证 Smooth 与 Visual Element Memory 是否可行”，推进到“把它们组织成一套可实验、可分析、可交互修正的长视频生成 pipeline”。整体思路是：用成熟短视频生成 API 负责单段生成，用 Smooth 处理相邻段短期运动连续性，用 Visual Element Memory 处理跨 shot 的中长期视觉一致性，再通过 notebook 式 Web UI 暴露每一步的中间结果、日志、参考图与人工修正入口。

## 主要进展

### 1. Visual Element Memory 从 CLI 方法推进到 Web notebook 流程

本周首先围绕新版 Web UI 设计了更轻量、项目自包含的 `videogen_notebook`。新系统不再依赖复杂全局数据库保存项目内部真相，而是让每个项目自己维护完整状态、资源和 Attempt 快照，从而天然支持复制、迁移、reset/fork 等创作者工作流。

随后将 Visual Element Memory pipeline 拆成六个清晰步骤：

1. Shot Design
2. Visual Elements Plan
3. Historical Reference Selection
4. Seedance Prompt Composition
5. Seedance Video Generation
6. Keyframe Maintaining

这使得原本黑盒式的一次性生成流程变成 notebook 式可观察流程：每一步都有独立状态、日志、产物表格和运行按钮。用户可以在关键中间结果生成后检查、编辑，再继续向下游推进。

### 2. 建立可交互的视觉元素计划与反思机制

在 Visual Elements Plan 阶段，本周完成了 AI 初步分析后的人工编辑能力：用户可以修改、添加、删除视觉元素行，并保存回 Attempt。保存后自动重置下游步骤，保持版本语义清晰。

此外实现了第一版 Visual Plan Reflect：LLM 会基于从第一个 shot 到当前 shot 的剧本上下文，检查当前 Visual Plan 中各元素的名称、类型、状态、备注和原因是否合理，并给出结构化修改建议。Web UI 中的 Reflect 按钮已接入后台任务；项目级也增加了 auto reflect 开关，使自动运行时可在 Step2 完成后自动执行一次反思再继续。

这一部分的意义在于：Visual Element Memory 不再只是一次性 LLM 输出，而是开始具备“生成初稿 - 自动审查 - 人工修正”的闭环。

### 3. 参考帧记忆从元素标注扩展到整体画面语义

本周进一步发现，关键帧只记录“有哪些元素可见”仍然偏碎片化，不足以指导 Seedance 对整张参考图进行整体性使用。因此新增了两类文本记忆：

- `holistic_description`：由 VLM 在关键帧维护阶段生成，描述画面中人物/物体/环境构成、构图/动作/氛围，以及该帧与当前剧情的关系。
- `reference_guidance`：由 LLM 在历史参考帧选择后生成，基于前序剧情和已选参考帧文本信息，说明为什么选择该参考帧，以及生成时应如何整体参考它。

Prompt 组装时，参考图说明现在变为：

```text
参考图片 Image N 来自 Scene / Shot：
整体画面描述
主观选择理由与应用指引

# 客观参考约束
应参考其中的：...
不应引入其中的：...
```

这样在保留原有客观元素覆盖/排除机制的同时，为 Seedance 增加了更自然的整体画面指引。重要的是，本周没有把这些整体描述纳入客观评分，避免过早混合两个不同维度；评分机制仍保持可解释、可消融。

### 4. 完善 notebook Web UI 的实验可用性

围绕实际实验使用，本周补齐了多项 Web UI 能力：

- Step3 Historical Reference Selection 表格展示参考帧、覆盖元素、排除元素、整体描述和 reference guidance。
- Step3 Edit 支持修改 `reference_guidance`、删除参考帧。
- Step6 Keyframe Maintaining 表格展示 produced keyframes 与 `holistic_description`。
- Step6 Edit 支持修改 `holistic_description`、删除关键帧。
- Step4 Seedance Prompt Composition 独立为可编辑步骤，使用户可在真实付费提交前检查和修改最终 prompt。
- 增加 Step review delay、Seedance 提交前人工确认、Current output 前缀缓存等机制，改善无人值守运行与人工审查之间的平衡。

这些改动让系统更接近一个面向创作者/研究者的实验平台，而不是单纯的脚本执行器。

### 5. 工程结构逐步转向可拓展实验平台

本周还完成了多个底层边界整理：

- 将 Seedance 生成、后处理、关键帧维护拆成更明确的 runner/postprocessor 边界。
- 项目内保存 `memory/visual_state.json` 与 `lineage.json`，记录 completed prefix 的视觉记忆状态。
- Run Shot / Run All 改为后台任务，避免长时间请求阻塞页面。
- Project bundle 保存完整 Attempt、asset manifest、final prefix output，便于复制、reset、fork 和分析。
- 默认真实 runner 已具备接入 Visual Element Memory、Seedance、Smooth reference video、关键帧抽取与 VLM 标注的完整路径。

这些工作服务于一个核心目标：后续研究可以不断替换选帧策略、参考图解释、Reflect 逻辑或 Prompt 组织方式，而不需要反复重写整个系统。

### 6. 初步测评与单视频记忆策略消融

本周也开始把“能生成”推进到“能评价”。虽然目前还不是完整实验体系，但已经完成了两项阶段性工作：

- **基于 VBench-Long 的简单一致性测评接入**：完成了在现有服务器环境中对单个本地长视频运行 VBench-Long 的基础流程，覆盖 subject/background consistency、motion smoothness、dynamic degree、aesthetic quality 和 imaging quality 等指标。这为后续自动评估不同记忆策略、连续性策略提供了第一版客观测评入口。
- **针对单个视频的记忆策略简单消融**：围绕同一生成视频/剧本，初步比较了不同记忆配置与参考策略下的中间结果和生成表现，验证了后续进行系统性消融的可行性。当前结果还不足以支撑强结论，但已经帮助明确了需要记录的变量：是否启用检索、参考帧数量、参考帧选择理由、错误元素泄漏、关键帧维护质量，以及最终视频一致性。

这两项工作可以视作“实验框架打通”的初步完成：一端有可切换的 agent pipeline，另一端有可运行的客观测评入口。下一步需要扩大样本、规范指标和人工评价维度，而不是停留在单例 smoke test。

## 当前阶段性认识

1. **连续性与记忆应分离建模**  
   Smooth 负责相邻 shot 的运动连续性；Visual Element Memory 负责跨 shot 的视觉元素一致性。二者应作为独立实验轴，而不是混在一个“参考图检索”问题里。

2. **历史参考图需要“局部元素约束 + 整体画面语义”两层说明**  
   只告诉模型“参考哪些元素”容易过于碎片；只告诉模型“参考整张图”又容易引入无关内容。本周新增的 holistic/reference guidance 是连接二者的中间层。

3. **长视频生成 agent 需要可审计中间状态**  
   LLM/VLM/Seedance 都可能出现解析错误、过度生成、错误引用或审核问题。将每一步拆成可视化表格、日志、prompt、raw response 和人工编辑入口，是提高实验效率和可维护性的关键。

4. **现阶段不宜过早复杂化评分机制**  
   目前应保持历史帧客观评分基于元素存在性与覆盖率。整体描述和主观 guidance 先用于解释和 prompt，不直接参与选帧分数，便于后续做清晰消融。

5. **测评体系需要同时包含客观指标和过程诊断**
   VBench-Long 可以提供一致性、运动、画质等整体指标，但它不能直接解释某张参考帧是否选错、某个元素是否泄漏。因此后续测评应同时记录 Web notebook 中的 Step 级中间状态、参考图选择、VLM 标注和人工 case 分析。
